# FE-03 — Accessible component fundamentals

## What I built

The `/playground/accessibility` page contains three hand-built React + TypeScript patterns. The project also includes components generated by the shadcn/ui CLI, but this exercise does not import them; keeping the two side by side makes the implementation trade-offs reviewable.

- **Modal dialog:** a labelled `role="dialog"` with `aria-modal="true"`, focus moved to the heading on open, a Tab/Shift+Tab loop, Escape and backdrop closing, an inert background, scroll lock, and focus restored to the trigger. A visible close button is included.
- **Tabs:** a horizontal `tablist` with one roving tab stop, selected state and panel relationships. Left/Right Arrow plus Home/End move focus and automatically select preloaded panels. Direction follows the document's LTR/RTL setting.
- **Disclosure:** a native button exposes `aria-expanded` and controls a labelled `region`; the collapsed panel uses the `hidden` attribute.

## Keyboard checklist

Use the page in a browser with the mouse untouched. Confirm that every focused control has a visible focus indicator.

1. **Dialog:** Tab to **Open sample dialog** and press Enter or Space. Focus should move to the dialog heading. Press Tab repeatedly through Close, the note field, Cancel, and Confirm; focus should wrap to Close. Press Shift+Tab from Close; focus should wrap to Confirm. Press Escape and confirm focus returns to **Open sample dialog**. Repeat, close with the visible close button, and repeat with Cancel. Clicking the backdrop should also close it.
2. **Tabs:** Tab into the tab list; only the selected tab should be a tab stop. Press Right Arrow through the tabs and confirm selection wraps to the first tab. Press Left Arrow to reverse. Press Home and End to jump to either end. Press Tab to enter the active panel, then continue out of the widget.
3. **Disclosure:** Tab to the disclosure button. Press Space, then Enter; each should toggle the content. Confirm `aria-expanded` changes with the visible state, and that collapsed content is skipped by keyboard navigation.
4. **Focus visibility:** navigate from the start of the page through every control with Tab and Shift+Tab. Confirm focus is not hidden behind the modal, clipped, or indicated by color alone.

These are manual verification steps; they are not a record that a browser, screen reader, automated scan, or audit was run.

## shadcn/ui source comparison

I inspected the official shadcn/ui repository's **New York v4 registry source**, linked below. This project also has the CLI-generated **Base Nova** dialog, tabs, and accordion components under `web/src/components/ui/`; those use Base UI primitives. The hand-built practice exercise does not import either version, so their interaction models can be compared directly.

| Pattern | Official source structure | This exercise | Concrete design gaps |
|---|---|---|---|
| Dialog | [`dialog.tsx`](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/new-york-v4/ui/dialog.tsx) composes Radix Dialog root, trigger, portal, overlay, content, close, title, and description primitives, then adds styling and convenience wrappers. | One focused sample flow, hand-managed inert siblings, focus loop, Escape, backdrop, scroll lock, and focus restoration. | The sample is intentionally not a reusable controlled/uncontrolled API. Its focusable-element query is a small hand-written approximation and does not cover every browser edge case, nested modal, or changing focusable content as comprehensively as a mature primitive. |
| Tabs | [`tabs.tsx`](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/new-york-v4/ui/tabs.tsx) forwards props to Radix Tabs and provides styled root/list/trigger/content wrappers, including orientation and style variants. | A fixed horizontal, automatic-activation tab set with roving focus, wraparound arrows, Home/End, and RTL direction handling. | No vertical orientation, manual activation, disabled tabs, controlled value, or configurable tab data/API. |
| Disclosure | [`accordion.tsx`](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/new-york-v4/ui/accordion.tsx) wraps Radix Accordion root/item/trigger/content and adds styling. | A single independent disclosure using a native button, `aria-expanded`, and a controlled region. | This is not a multi-item accordion; it has no single/multiple expansion mode, collapsible-group policy, animation, or reusable composition API. |

The trade-off is instructional control: this exercise makes the state and keyboard behavior visible in a small implementation, while the installed Base Nova components delegate interaction details to Base UI and provide composable wrappers and styling. The New York source links in the comparison illustrate another official shadcn style that composes Radix primitives.

The installed generated source is in `web/src/components/ui/dialog.tsx`, `tabs.tsx`, and `accordion.tsx`. The CLI setup is recorded in `web/components.json`; the components use the `@base-ui/react` primitives. The accessible playground remains hand-built rather than wrapping those primitives.

## What I learned

- ARIA communicates state and relationships; it does not supply keyboard behavior or make a background modal-inert by itself.
- Roving `tabIndex` keeps a tab set to one page-level stop, while arrow keys handle movement within the widget.
- A native button already supports Enter and Space, so the disclosure only needs its state and panel relationship to be communicated.
- The simple focusable-element scan is useful for this fixed example, but modal focus management has enough edge cases that a maintained primitive is a safer production default.
